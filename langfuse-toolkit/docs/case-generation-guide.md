# 用 Langfuse 生成 Case：操作指南

这份指南用于生成母婴咨询的单轮用例，并整理成可交给医生审核的材料。

一条 Case 包含：**用户问题、用户画像、候选安全分类、初步判断及依据、可能的问诊回应、必要追问**。

整个流程：**Langfuse 生成问题与画像 → 收集器编号 → Langfuse 生成候选问诊材料 → 收集器合并、导出 → 医生审核**。

## 开始前

- 打开团队的 **Langfuse 项目**，确认能访问下面两个 Prompt。
- 打开 [Output 收集器](http://172.17.23.51:3722)，需连接公司内网。首次使用点「注册」，用自己的邮箱和密码创建账号；之后直接登录。
- 确认本次要生成的场景和数量，使用团队确认过的 Prompt 版本及模型配置。本文以 **S01「孕期与待产准备」，生成 6 条**为例。

| Prompt 名称 | 用途 |
|---|---|
| `medical/user-question-generator` | 生成用户问题和画像 |
| `medical/case-review-draft` | 根据问题和画像，生成供医生审核的候选材料 |

收集器账号独立于 Langfuse。每个人有自己的工作空间，接收成功的内容会保存到服务器，换电脑登录同一账号可以继续。

## 第 1 步：生成问题与画像

在 Langfuse 打开 `medical/user-question-generator`，进入 Playground，按下面的示例填写变量后运行。

| 变量 | 本次示例 | 怎么填 |
|---|---|---|
| `count` | `6` | 本次生成几条 |
| `scenario` | `S01｜孕期与待产准备` | 场景编号和名称 |
| `requirements` | `按场景默认` | 有额外的人群、阶段、风格或对照要求时，写在这里 |
| `source_materials` | `[]` | 没有参考素材时填 `[]` |
| `existing_questions` | `[]` | 首次生成可填 `[]`；继续补充时放入已有问题和画像，帮助避免重复 |

其他场景的填写参考见 [场景与生成要求](variables.md)。正式批次按分配的场景和数量生成。

运行完成后，快速看一下：数量是否正确、问题是否符合场景、有无明显重复。结果应包含 `questions` 数组。复制 **Output 中的完整 JSON**，不要只复制某一条问题。

## 第 2 步：把问题交给收集器

回到收集器左侧「问题与画像」：

1. 填写「编号前缀」，例如 `S01-B01`，表示 S01 场景的第 1 批。
2. 把刚才的完整 Output 粘贴到「第一个 Output」。
3. 点击「收下问题与画像」，确认新增了 6 条问题。

收集器会自动生成编号，例如 `Q001` 变成 `S01-B01-Q001`。后面两份材料就靠这个编号对应起来。

**新一批用新前缀**，例如 `S01-B02`。多人最后需要合并 CSV 时，可在前缀中加上各自约定的缩写，例如 `S01-ZS-B01`，避免编号重复。

## 第 3 步：生成候选问诊材料

1. 在收集器中间的「范围」选择刚才的批次，例如 `S01-B01`。
2. 点击「复制整批问诊输入（6 条）」。复制的内容已带齐每条问题的编号、问题原文和画像。
3. 回到 Langfuse，打开第二个 Prompt：`medical/case-review-draft`。
4. 把复制的整段内容粘贴到变量 `case_input`，运行。

第二个 Prompt 应返回包含 `reviews` 数组的完整 JSON。本次输入 6 条，就应返回 6 条材料。**保持收集器生成的完整编号，不手动删改前缀或重新编号。**

> 【在此插入截图：收集器的批次选择和复制按钮，以及第二个 Prompt 的 case_input 和 Output】

## 第 4 步：合并两份材料

复制第二个 Prompt 的完整 Output，回到收集器右侧「医生审核材料」：

1. 粘贴到「第二个 Output」。
2. 点击「收下医生审核材料」。
3. 查看列表，确认本批每条都显示「材料已配齐」。

如果工作空间中只有这批 6 条，顶部应显示：**6 条问题、6 已配齐、0 待补材料、0 待关联**。已有其他批次时，顶部显示的是整个工作空间的合计。

可以点击列表中的「查看」，抽查问题、画像与候选材料是否对应。

## 第 5 步：导出并交付审核

确认材料配齐后，分别点击：

- **「下载 CSV」**：用于查看、交付和后续标注，一行对应一条 Case。
- **「下载 JSON 备份」**：保留完整原始材料，便于恢复和继续整理。

**CSV 会导出当前账号工作空间中的全部问题。** 中间的「范围」只控制复制给第二个 Prompt 的内容，不会筛选 CSV 的导出范围。

交付时同时注明：场景、批次前缀、数量、两个 Prompt 的实际版本、模型及主要参数。这些运行信息需要自行记录，收集器不会自动补齐。

**「材料已配齐」表示候选材料齐全，仍需医生审核。** 医生查看问题和画像后，确认或修改安全分类、初步判断、回应方向和追问。导出时医生确认栏留空，由人工填写。

## 遇到问题时

| 现象 | 处理方式 |
|---|---|
| 提示 JSON 不完整或格式不正确 | 重新复制完整 Output；如果生成结果被截断，减少每批数量后重跑 |
| 提示同编号的问题内容不同 | 新批次改用新前缀，如 `S01-B02`，再接收；确认没有误把新内容放进旧批次 |
| 显示「待补问诊」 | 这条问题还没有对应的第二份材料，补生成并接收后再检查 |
| 显示「待关联问题」 | 核对第二份材料的 Case ID 是否与已有问题完全一致，检查问题是否已接收；有待关联材料时不能导出 CSV |
| 重新生成的问诊材料无法接收 | 确认要更新后，勾选「用新材料替换同编号的旧问诊材料」，再接收 |
| 点击复制没有成功 | 如弹出文本框，选中内容后用 Ctrl+C / ⌘C 手动复制 |

本批完成的检查：**问题数量符合任务、候选材料逐条配齐、CSV 和 JSON 已下载、生成版本及模型信息已记录。**
